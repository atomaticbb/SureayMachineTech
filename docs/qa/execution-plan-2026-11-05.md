# Sureay 前端 QA 执行方案

本文件保留完整 QA 方案。本轮按用户确认的 P0、当前改动收尾及后续人工视觉修订执行。结果和复测入口见 scope-closeout.md 与 local-validation.md。原始证据保存在 qa-results/full-qa。此文与 qa-plan-amendments.md 有冲突时，以最新已确认的 design.md 和 design-decisions.md 为准。

## 已确认边界

- 唯一规范域名 https://sureay.com；www 永久跳转并保留路径和查询参数。
- D01–D07 均已确认；主 CTA 按后续确认的句首大写规范使用 Request a quote；日期 DD MMM YYYY；仅亮色。
- Metropolis 500/600/700、Inter Variable 一个文件、IBM Plex Mono 400/500；Latin、自托管、swap；六文件以内；字号 +2 后向上归偶数、最低 12px。
- 自动化先跑，随后人工浏览器检查、外部验证和同环境复测。修复开发不计入原 43–62 人时估算。
- 执行：Codex；业务与本地最终验收：Yu。邮件测试仅发至 用户指定的测试邮箱（通过 QA_TEST_EMAIL 配置），使用独立数据库与收件覆盖。真实收件、iOS/Android 真机及 NVDA/VoiceOver 不以模拟通过替代。
- 不部署、不推送 Git；完成后交付本地验证入口，等待 Yu 验证与推送决定。
- 字体调整已先行，因此全 QA 的“修复前”基线取当前线上版本；当前本地字体状态另存中间基线。二者不可用于把所有指标变化单独归因于字体。

## 执行、证据与分级

所有命令在仓库根目录 PowerShell 执行。依次运行 pnpm type-check、pnpm lint、pnpm test、pnpm build:full、pnpm test:seo、pnpm test:build、pnpm test:e2e（按脚本所需服务启动）。完整构建含预渲染与目录生成。生产静态/API 用 Express 验证，Vite preview 只用于布局迭代。

每个检查项记录 ID、样本、视口/浏览器、执行方式、期望/实际、通过/未通过/待确认、不适用理由、问题 ID、证据路径、修复与复测版本。P0 为核心链路丢失/全站不可用，P1 为关键功能不可用/不可访问/不可索引，P2 为局部功能或性能缺陷，P3 为轻微外观或兼容加固。所有 P0/P1 必须同条件复测。

样本由 scripts/qa-samples.ts 从数据源生成：首页、products、8 产品、3 行业、全部 mixer 树、3 文章含最长 Ni-Hard 文章、about、contact；另加分类/news/法律页、各语言首页/产品/联系页及无效路径。自动 SEO/链接检查覆盖所有公开路由。

视口：360×640、390×844、412×915、844×390、768×1024、1024×768、1366×768、1440×900、1920×1080。所有样本执行布局采集；关键链路在各尺寸及桌面 200% 缩放验证。设备模拟与真机分列。

Lighthouse 固定 12.8.2，移动端冷缓存每样本串行三次，保存 JSON/HTML 与首屏/全页截图；分别计算 LCP/CLS 中位数。CPU、网络、浏览器和 Consent 状态一致。线上和本地区分报告，不混合计算中位数。
